# Maze Escape — подготовка к защите (5 минут)

## Что делает программа

1. **DSU / Union-Find** хранит группы связанных клеток. `find` находит корень группы, `union` соединяет две группы, только если они различаются. Оптимизации: **union by size** и **path compression**.
2. **Build Maze** — открываем стены по порядку файла, когда `union` возвращает `true`. Получается дерево из `n-1` открытой стены (при `n` клетках).
3. **Kruskal** — сортируем стены по весу и включаем только те, которые соединяют разные компоненты. **Prim** — начинаем с одной клетки, выбираем минимальную границу дерева с помощью `PriorityQueue`. Их итоговые стоимости MST равны.
4. **DFS** — из клетки 0 ищем выход `n-1`; проверяем соседей строго в порядке **вверх, вправо, вниз, влево**. Используем собственный стек в массивах, а не рекурсию. `visited` — число посещённых клеток в момент первого посещения выхода.
5. **Kosaraju** — два DFS: первый на обычном ориентированном графе записывает порядок завершения, второй на обратном графе извлекает SCC (сильно связные компоненты).
6. **SCC DAG** — после сжатия компонент получается DAG: из компоненты в следующую ведут направленные рёбра. В порядке номеров компонент считаем максимальную длину цепочки и минимальное время от входа до выхода.

## Возможные вопросы

**Почему DSU работает быстро?** Path compression делает почти все вершины детьми корня, union by size ограничивает высоту. Операции `find/union` практически константные, формально `O(α(n))` амортизированно.

**Почему именно `n-1` сломанных стен?** Стартуем с `n` компонент связности. Каждая новая открытая стена уменьшает число компонент на 1; до одной компоненты нужно `n-1` соединений, без циклов.

**Чем Kruskal отличается от Prim?** Kruskal сортирует *все рёбра* и использует DSU; Prim растит *одно дерево* из стартовой вершины, выбирая ближайшую к нему новую вершину. Оба решают MST.

**Почему единственный путь?** Проходы образуют связное дерево. В дереве два разных простых пути дали бы цикл, что невозможно.

**Зачем Kosaraju обратный граф?** Чтобы во втором обходе получить SCC целиком, не зайдя по исходящим рёбрам в другие компоненты. Порядок завершения первого прохода помогает выбирать их в нужной последовательности.

**Когда `Is DAG = 1`?** Когда на направленных слайдах нет циклов, то есть каждая SCC состоит из одного узла (`Zones == n`). Самопетель нет по условию.

**Почему для кратчайшего пути между SCC не используем Dijkstra?** Граф после сжатия SCC ацикличен, номера SCC топологически отсортированы. Поэтому все входящие пути обработаны к моменту перехода к очередной SCC: хватает одного прохода по рёбрам `O(z+s)`.

**Что в файле `walls.txt`?** `R C W` — размеры и число внутренних стен; далее `a b w` — клетка, соседняя клетка, стоимость удаления стены; индекс стены в Java на 1 меньше номера строки.

**Что в файле `slides.txt`?** `n S` — количество клеток и слайдов; далее `a b t` — направленный слайд `a -> b` со временем `t`.
